# A01 MVP Core Delivery 架构设计（PRD 1.0.0）

## 目标

在 Android 运行、Web 调试的约束下，交付规则驱动阅读器 MVP，覆盖从规则导入到内容浏览、错误处理、验收与发布的完整主链路。

核心目标：

- 建立稳定规则契约与可校验导入流程
- 建立可扩展的 HTML 抓取与解析运行时
- 建立图片/视频基础阅读能力
- 建立可发布、可验收、可回归的工程基线

## 关键设计

### 1. 分层与模块边界

- 代码按 `core` 与 `features` 分层：
  - `core`：模型、存储契约、日志、错误策略、缓存等共性能力
  - `features`：按业务能力拆分 `data/domain/presentation`
- 页面与运行时通过 loader/service 连接，避免 UI 直接依赖底层抓取细节。

### 2. 规则导入与校验链路

- 导入链路：Raw URL 输入 -> 下载 -> 预处理 -> JSON 解析 -> 结构化校验。
- 校验器输出结构化问题列表（`code/path/message`），用于页面精确反馈。
- 校验失败在导入阶段拦截，避免坏规则进入后续运行时。

### 3. 运行时抓取与解析引擎

- 统一抓取器负责请求、超时、响应规范化。
- 提取器引擎支持 selector/function/regex/absoluteUrl 等规则能力。
- 运行时服务统一编排 `index/detail/content` 三类解析入口，屏蔽调用方差异。

### 4. 数据契约与存储抽象

核心模型：

- `SiteRecord`、`RuleSnapshot`：站点与规则快照
- `CatalogEntry`、`DetailEntry`、`ContentPayload`：运行时解析结果
- `ReadingHistoryEntry`：阅读进度

存储抽象：

- `SiteStore`、`RuleStore`、`ReadingHistoryStore`、`AppStorage`
- 在 MVP 阶段冻结接口，不绑定具体数据库实现。

### 5. 页面流程编排

主流程：

- 站点导入 -> 站点列表 -> 目录页 -> 详情页 -> 内容页（图片/视频）

页面职责：

- 页面层负责状态展示（加载/空态/错误）
- 业务动作通过 loader/service 执行
- 页面只消费结构化结果，不处理抓取细节

### 6. 媒体阅读能力

- 图片链路：解析图片 URL 列表 -> 阅读器支持点击/滑动翻页与页码展示。
- 视频链路：解析视频 URL -> 播放器完成基础播放控制。
- 能力边界保持 MVP 最小可用，不引入复杂播放增强与跨端高级能力。

### 7. 错误策略与日志

- 统一错误策略：
  - dev：展示详细错误信息
  - prod：展示用户友好兜底文案
- 日志组件统一收口内部诊断信息，避免错误处理散落在页面层。

### 8. 缓存与性能基线

- 抓取侧引入短期 TTL 缓存（请求级）与超时归一化。
- 阅读侧引入邻近资源预取，降低连续翻页感知延迟。
- 所有优化以“不改变业务行为”为前提。

## 向后兼容

- 规则版本保持 `1.0`，兼容既有 schema 与样例。
- 运行时改动优先通过服务层与模型兼容桥接，避免页面接口频繁破坏性调整。

## 已知限制

- 对依赖重度 JS 运行或强反爬策略的网站，MVP 直连抓取成功率有限。
- 当前缓存以内存为主，未提供持久化缓存。
- 当前日志仅用于本地诊断，未接入远端日志管道。
