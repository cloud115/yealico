# 安卓版站点内容净化阅读器 PRD (v1.0.1 增量更新)

## 1. 版本迭代背景
**关联版本**：基于 v1.0.0 核心流程（规则导入 -> 净化阅读）。
**核心痛点**：v1.0.0 验收时发现，目标站点普遍存在反爬策略（Cloudflare 防火墙、UA 校验、图片防盗链、JS 数据加密）。若底层抓取引擎仅使用简单的 HTTP 请求，将导致大量站点规则失效，用户频繁看到“解析失败”。
**迭代目标**：增强底层内容抓取能力，模拟真实浏览器行为，提高站点规则解析成功率。

## 2. 核心机制增强详述

### 2.1 内核渲染引擎切换
- **现状 (v1.0.0)**：可能存在直接使用轻量级网络请求库（如 OkHttp）获取 HTML 源码。
- **v1.0.1 变更**：
    - **强制启用 WebView 预渲染机制**：在解析站点内容前，必须使用隐藏的系统 WebView（Android WebView 内核）加载目标 URL。
    - **等待页面稳定**：监听 WebView 的 `onPageFinished` 及 DOM 加载完成事件，确保页面内 JavaScript（包括反爬验证脚本）执行完毕。
    - **验证通过后再提取**：从渲染完成的 WebView 中获取真实的 HTML 结构，而非单纯请求源码字符串。

### 2.2 请求头与身份模拟
为了绕过基础的 UA 检测和图片防盗链，规则导入后需支持以下参数的动态配置与覆盖：

| 参数项 | 作用 | v1.0.1 实现要求 |
| :--- | :--- | :--- |
| **User-Agent** | 伪装客户端类型 | 规则脚本中可指定 UA 字符串。若规则未指定，App 默认使用 **移动端 Chrome 最新版 UA**。 |
| **Referer** | 绕过图片防盗链 | 请求图片资源时，**强制**将当前站点主页 URL 作为 Referer 携带在请求头中。 |
| **Cookie 同步** | 维持登录态/验证态 | WebView 加载页面过程中产生的 Cookie（如 `cf_clearance`）**自动持久化**，并在后续抓取图片/视频链接时自动携带。 |

### 2.3 自定义 JavaScript 注入接口
为应对数据加密（如 Base64 乱码、动态拼接 URL），规则需具备“二次加工”能力。

- **接口定义**：App 需暴露一个 JavaScript 桥接对象（例如 `window.AndroidParser`），但此处需求与桥接无关，而是支持**规则自带解密脚本**。
- **执行逻辑**：
    1. WebView 加载目标页面完成。
    2. App 读取规则文件中定义的 **`decryptScript`** 字段（一段纯 JS 代码）。
    3. 通过 `webView.evaluateJavascript()` 将该脚本注入页面并执行。
    4. 脚本执行完毕后，返回解析好的 **图片列表数组** 或 **视频直链字符串** 给原生层。
- **典型用例**：网页源码中只有一串密文，JS 解密后返回真实图片 URL 列表。

### 2.4 请求频率与并发控制
防止因抓取过快触发服务端限流（429 错误）或临时 IP 封禁。

- **图片预加载策略**：
    - 阅读器模式下，**仅预加载当前页的前 2 页和后 2 页**。
    - 单域名下的图片请求并发数限制为 **3 个**。
    - 请求间隔（Throttle）设置为 **200ms**。
- **列表加载策略**：获取目录列表时，若连续两次请求失败（非网络错误），自动暂停抓取并向用户提示“站点限流，请稍后重试”。

### 2.5 异常流程扩展 (反爬相关)
在 v1.0.0 的“解析失败”基础上，细化提示以辅助用户和规则维护者定位问题。

| 异常场景 | 检测机制 | 用户提示文案 |
| :--- | :--- | :--- |
| **WebView 加载 5 秒盾/验证页超时** | 页面标题或 URL 包含 `cloudflare`、`challenge` 且未自动跳转 | `Toast: 站点验证中，请检查网络或稍后重试` |
| **图片请求返回 403** | HTTP 状态码检测 | `Toast: 图片防盗链拦截，请更新规则` |
| **JS 注入脚本执行报错** | `evaluateJavascript` 回调返回异常 | `Toast: 规则脚本执行异常` |

## 3. 对 v1.0.0 规则的兼容性影响
- **向下兼容**：未使用新特性（无 `decryptScript`、无特殊头配置）的旧规则，App 将使用默认增强后的 WebView 引擎抓取，解析成功率会自然提升，**无需修改旧规则文件**。
- **规则格式预留**：建议在规则 JSON 中预留以下字段：
    - `userAgent` (String, Optional)
    - `decryptScript` (String, Optional)
    - `refererPolicy` (String, Optional, 默认 `origin`)

## 4. 验收标准 (v1.0.1 专项)

| 验收场景 | 操作步骤 | 预期结果 |
| :--- | :--- | :--- |
| **Cloudflare 防护站点** | 导入支持某 Cloudflare 漫画站的规则 | 列表加载稍慢（5秒内），加载完成后成功显示目录，不再直接提示解析失败 |
| **图片防盗链站点** | 浏览一个图片只在站内显示的图集 | 阅读器内图片正常展示，无裂图（403）现象 |
| **加密数据解密** | 规则中包含 `decryptScript` 进行简单 Base64 解码 | 图片列表正确展示，与网页端看到的一致 |
| **高频抓取限流** | 快速连续翻页 20 页 | App 响应流畅，图片一张张加载，无应用无响应 (ANR) 现象，不出现 IP 被封提示 |
| **Cookie 持久化** | 在内置 WebView 手动登录某论坛 -> 返回目录刷新 | 目录列表显示登录后才能看的版块内容 |
